# نقش‌ها و دسترسی‌های مالی

نقش‌ها گروه‌های Django هستند و با هر `python manage.py migrate` از `apps/audit/roles.py` به‌روز می‌شوند. همه کنترل‌ها سمت سرور است: مجوز Django در صفحات، API و پنل، به‌علاوه کنترل مالکیت و «نفر دوم» در سرویس‌ها.

## اصول

- **کمترین دسترسی:** هر نقش فقط مجوزهای کار خودش را دارد. هیچ نقش مالی به پرونده پزشکی، تشخیص، جواب آزمایش یا متن گفتگوی مشاوره دسترسی ندارد (با تست کنترل می‌شود).
- **جدایی مالی از بالینی:** پزشک با نقش «پزشک» پرونده بیماران خودش را می‌بیند ولی صورتحساب و دفاتر را نه؛ فقط سهم و تسویه خودش را. کاربران مالی صورتحساب را با نام و شناسه بیمار، کد خدمت و مبلغ می‌بینند و کد ملی در صفحه صندوق ماسک می‌شود.
- **چهار چشم:** در سرویس‌ها کنترل می‌شود، پس حتی کاربری با چند نقش نمی‌تواند سند خودش را تأیید کند (`FINANCE_RULES["four_eyes"]`).
- **گزارش تغییرات:** ایجاد، تغییر، ثبت، برگشت، تأیید، تغییر وضعیت و تغییر قابلیت‌ها در `AuditLog` با کاربر، زمان و IP.

## نقش‌ها

| نقش | می‌تواند | نمی‌تواند |
|---|---|---|
| مدیر کل (مدیر مجموعه) | اجتماع نقش‌های مدیریتی، از جمله مدیر مالی، تأییدکننده پرداخت و منابع انسانی | پرونده پزشکی و جواب آزمایش |
| مدیر مالی | همه اسناد و گزارش‌ها، تخفیف، تأیید استرداد و نسخه قرارداد، وضعیت قرارداد، تأیید مالی تسویه، ثبت تسویه، تأیید و ثبت حقوق، نرخ‌های حقوق و جدول مالیات، بستن دوره، تنظیمات قابلیت‌ها، تلاش مجدد رویداد | تأیید سند خودش؛ داده بالینی |
| حسابدار | اسناد داروخانه و پرداخت‌ها (مثل قبل)، ثبت و برگشت صورتحساب و دریافت، سند دستی (ثبت، نه برگشت)، مغایرت بانک، محاسبه تسویه، گزارش‌ها، دیدن صف رویداد | تخفیف، تأیید استرداد، تأیید تسویه، حقوق |
| صندوق‌دار | صندوق داروخانه (مثل قبل) و صندوق درمانگاه: صورتحساب از تعرفه، دریافت، ثبت درخواست استرداد و پرداخت استرداد تأییدشده | تخفیف، تأیید استرداد، برگشت، گزارش مالی، حقوق |
| تأییدکننده پرداخت | تأیید استرداد، تأیید مدیریتی تسویه، تأیید نسخه قرارداد؛ دیدن همان اسناد | ساخت یا ثبت نهایی سند |
| مسئول منابع انسانی | پرونده حقوقی کارکنان، اقلام ثابت، قرارداد کارکنان، وام (ثبت و برگشت)، ساخت و محاسبه لیست حقوق | تأیید و ثبت حقوق، تغییر نرخ اقلام و جدول مالیات |
| حسابرس | فقط مشاهده همه اسناد مالی، دفاتر، گزارش‌ها، حقوق، صف رویداد، قابلیت‌ها و گزارش تغییرات | هر تغییر (همه مجوزهایش view است؛ با تست کنترل می‌شود) |
| پذیرش درمانگاه، منشی پزشک | دیدن وضعیت صورتحساب و دریافت | دریافت وجه، صدور صورتحساب |
| پزشک | صفحه «سهم و تسویه من» و API آن، فقط برای قرارداد خودش و فقط تسویه‌های غیرپیش‌نویس | تسویه دیگران، صورتحساب، دفاتر |
| کارمند (هر کاربر با پرونده حقوقی) | فیش حقوق خودش پس از ثبت نهایی | فیش دیگران |
| مدیر داروخانه، مدیر آزمایشگاه | مثل قبل، به‌علاوه دیدن مراکز هزینه | — |

نقش «مدیر کلینیک» در درخواست، همان «مدیر کل» موجود است. اگر لازم باشد مدیر کل نتواند تأیید مالی بدهد، باید او را فقط با نقش‌های لازم تعریف کرد؛ کنترل نفر دوم در هر حال برقرار است.

## API

- بدون ورود: `401` با JSON استاندارد. بدون مجوز: `403`. ورودی نامعتبر: `400`. هیچ stack trace برگردانده نمی‌شود.
- `POST /finance/api/v1/receipts/` سرآیند `Idempotency-Key` (۸ تا ۶۴ نویسه) لازم دارد؛ تکرار همان کلید همان دریافت را برمی‌گرداند. احراز هویت با نشست و توکن CSRF Django است (`csrf_exempt` نیست).
