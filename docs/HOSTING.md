# راه‌اندازی سامانه ۷۲۴ روی هاست cPanel

این راهنما سامانه را روی هاست اشتراکی cPanel با پایگاه داده MySQL/MariaDB نصب می‌کند (مثلاً روی 724med.ir). همه کارها با یک اسکریپت انجام می‌شود: `deploy/cpanel/install.sh`. برای سرور اختصاصی (VPS) راهنمای [DEPLOY.md](DEPLOY.md) را ببینید.

## پیش‌نیازها

- هاست cPanel با **دسترسی SSH/Terminal** و **Application Manager** (پشتیبانی پایتون). اگر در cPanel گزینه Terminal را نمی‌بینید، از پشتیبانی هاست بخواهید فعالش کنند.
- دامنه روی همین هاست تنظیم شده باشد.
- پایتون 3.10 یا جدیدتر لازم نیست: اگر پایتون سرور قدیمی باشد، اسکریپت یک پایتون 3.12 مستقل در پوشه حساب نصب می‌کند.

## ساختار پوشه‌ها روی هاست

```
~/724/app            کد برنامه (git) و فایل تنظیمات .env
~/724/venv           محیط پایتون
~/724/static         فایل‌های ثابت (CSS)
~/724/media          تصاویر عمومی (پزشک، کالا)
~/724/private_media  مدارک اسکن‌شده بیماران؛ هرگز از وب سرو نمی‌شود
~/724/backups        پشتیبان‌ها
~/724/logs           لاگ برنامه
```

هیچ فایلی در `public_html` قرار نمی‌گیرد.

## ۱. نصب

در cPanel صفحه **Terminal** را باز کنید و این دستور را کپی و اجرا کنید:

```bash
cd ~ && git clone -q https://github.com/abdollah1366/724.co.ir.git 724-setup && DOMAIN=724med.ir bash 724-setup/deploy/cpanel/install.sh; rm -rf ~/724-setup
```

اسکریپت این کارها را انجام می‌دهد:

1. یک پایتون مناسب پیدا یا نصب می‌کند.
2. کد را در `~/724/app` می‌گیرد و بسته‌ها را نصب می‌کند.
3. **پایگاه داده و کاربر آن را خودش با API خود cPanel می‌سازد**، با رمز تصادفی قوی. اگر نشد، از شما می‌خواهد در **MySQL Database Wizard** بسازید و نام و رمز را در همان Terminal وارد کنید. رمز را هیچ‌جای دیگر ننویسید.
4. تنظیمات امن را در `~/724/app/.env` می‌نویسد، جدول‌ها و اطلاعات پایه را می‌سازد.
5. برنامه را در **Application Manager** ثبت می‌کند.

اجرای دوباره اسکریپت امن است. رمزها و داده‌ها حفظ می‌شوند.

در پایان، آدرس سایت و **آدرس پنل مدیریت** چاپ می‌شود. آدرس پنل تصادفی است (مثل `/manage-3fa9c1d2e7/`) تا قابل حدس نباشد. آن را یادداشت کنید. بعداً هم با `grep DJANGO_ADMIN_URL ~/724/app/.env` دیده می‌شود.

### اگر ثبت در Application Manager خودکار انجام نشد

در cPanel > **Application Manager** > **Register Application**:

| فیلد | مقدار |
|---|---|
| Application Name | `724` |
| Deployment Domain | `724med.ir` |
| Base Application URL | `/` |
| Application Path | `724/app` |
| Deployment Environment | `Production` |

دکمه **Deploy** را بزنید. بخش Environment Variables را خالی بگذارید، چون تنظیمات در `.env` است. دکمه «Ensure dependencies» را هم نزنید، چون بسته‌ها را خود اسکریپت نصب کرده است.

## ۲. گواهی HTTPS

سایت فقط با HTTPS کار می‌کند. در cPanel > **SSL/TLS Status**، دامنه‌های `724med.ir` و `www.724med.ir` را انتخاب و **Run AutoSSL** را بزنید. صدور گواهی ممکن است چند دقیقه طول بکشد.

## ۳. ساخت حساب مدیر ارشد

در Terminal:

```bash
cd ~/724/app && ~/724/venv/bin/python manage.py createsuperuser
```

سپس با آدرس پنل مدیریت وارد شوید.

## ۴. کارهای زمان‌بندی‌شده (Cron Jobs)

در cPanel > **Cron Jobs**، این شش کار را اضافه کنید. در هر کدام، زمان را در فیلدهای Minute/Hour بنویسید و دستور را در Command. به‌جای `med` نام کاربری هاست خودتان را بنویسید.

| زمان | Minute | Hour | Command |
|---|---|---|---|
| ۲:۳۰ بامداد: پشتیبان | `30` | `2` | `BACKUP_KEEP_DAYS=14 bash /home/med/724/app/deploy/tasks.sh backup` |
| ۰۰:۳۰: انقضای دارو، پاک کردن نشست‌ها | `30` | `0` | `bash /home/med/724/app/deploy/tasks.sh nightly` |
| ۱۰ صبح: پیامک‌های یادآوری | `0` | `10` | `bash /home/med/724/app/deploy/tasks.sh reminders` |
| هر ۱۰ دقیقه: مشاوره آنلاین (انقضا، یادآوری ویزیت) | `*/10` | `*` | `bash /home/med/724/app/deploy/tasks.sh telemed` |
| هر ۵ دقیقه: تلاش مجدد رویدادهای بین‌ماژولی (مالی) | `*/5` | `*` | `bash /home/med/724/app/deploy/tasks.sh events` |
| ۱:۱۵ بامداد: قراردادها و کنترل مغایرت مالی | `15` | `1` | `bash /home/med/724/app/deploy/tasks.sh finance` |

برای بقیه فیلدها (Day، Month، Weekday) علامت `*` بگذارید. ساعت‌ها به وقت سرور است؛ ساعت سرور در بالای صفحه Cron Jobs نمایش داده می‌شود. ایمیل خروجی را می‌توانید در همان صفحه تنظیم کنید تا از خطاها باخبر شوید.

## ۵. تنظیمات

تنظیمات در `~/724/app/.env` است. با **File Manager** باز کنید (از Settings گزینه Show Hidden Files را روشن کنید) یا در Terminal بنویسید `nano ~/724/app/.env`. این فایل رمز پایگاه داده را دارد؛ با کسی به اشتراک نگذارید.

| کلید | توضیح |
|---|---|
| `SITE_PHONE`، `SITE_ADDRESS` | تلفن و نشانی در پایین صفحات |
| `SMS_BACKEND`، `SMS_API_KEY`، `SMS_SENDER` | پیامک. تا `console` است، پیامک‌ها فقط در لاگ ثبت می‌شوند |
| `PAYMENT_GATEWAY` | درگاه پرداخت مشاوره آنلاین. پیش‌فرض `none`: پرداخت اینترنتی خاموش و ثبت دستی در پنل ([TELEMED.md](TELEMED.md)) |
| `LAB_NAME`، `LAB_LICENSE_NO`، `LAB_TECHNICAL_DIRECTOR`، ... | مشخصات آزمایشگاه روی برگه جواب |
| `CLINIC_NAME` | نام درمانگاه در پیامک و مانیتور صف |
| `DJANGO_HSTS_SECONDS` | ابتدا ۳۶۰۰. وقتی HTTPS چند روز درست کار کرد، آن را `31536000` کنید |

بعد از هر تغییر، برنامه را دوباره راه‌اندازی کنید:

```bash
touch ~/724/app/tmp/restart.txt
```

## ۶. به‌روزرسانی به نسخه جدید

```bash
bash ~/724/app/deploy/cpanel/update.sh
```

این دستور اول پشتیبان می‌گیرد، بعد کد، بسته‌ها و پایگاه داده را به‌روز و برنامه را دوباره راه‌اندازی می‌کند. شناسه نسخه قبلی را هم چاپ می‌کند.

**بازگشت به نسخه قبلی:**

```bash
git -C ~/724/app checkout <شناسه-نسخه-قبلی> && touch ~/724/app/tmp/restart.txt
```

اگر نسخه جدید جدول‌های پایگاه داده را تغییر داده بود، پشتیبانی را که update.sh پیش از تغییر گرفته بود برگردانید (بخش ۷).

## ۷. پشتیبان‌گیری

- با Cron بالا، هر شب از پایگاه داده و پوشه مدارک بیماران پشتیبان فشرده گرفته می‌شود. صحت فایل بررسی و کد SHA-256 کنارش ذخیره می‌شود. نسخه‌های قدیمی‌تر از ۱۴ روز حذف می‌شوند، چون فضای هاست محدود است.
- پشتیبان دستی: `bash ~/724/app/deploy/tasks.sh backup`
- فهرست پشتیبان‌ها: `ls -lh ~/724/backups`

**پشتیبان باید بیرون از هاست هم نگهداری شود.** دست‌کم هفته‌ای یک‌بار، آخرین فایل‌های `~/724/backups` را با File Manager دانلود کنید. این فایل‌ها اطلاعات پزشکی بیماران را دارند؛ فقط روی دیسک رمزگذاری‌شده (مثلاً BitLocker) نگهشان دارید.

**بازگرداندن پشتیبان:**

```bash
cd ~/724/app
gunzip -c ~/724/backups/db-YYYYMMDD-HHMMSS.sql.gz | ~/724/venv/bin/python manage.py dbshell
# مدارک بیماران (اگر فایل files-... وجود دارد):
~/724/venv/bin/python -m zipfile -e ~/724/backups/files-YYYYMMDD-HHMMSS.zip ~/724/private_media/
touch ~/724/app/tmp/restart.txt
```

## ۸. امنیت

اسکریپت این موارد را انجام می‌دهد: حالت DEBUG خاموش، رمزهای تصادفی قوی، HTTPS اجباری و کوکی‌های امن، آدرس تصادفی پنل مدیریت، و نگهداری مدارک بیماران و پشتیبان‌ها بیرون از پوشه وب با دسترسی فقط برای حساب شما.

کارهایی که خودتان باید انجام دهید:

1. **ورود دومرحله‌ای cPanel** را روشن کنید (cPanel > Two-Factor Authentication). هر کس به cPanel دسترسی داشته باشد، به اطلاعات بیماران دسترسی دارد.
2. رمز cPanel را قوی کنید و به کسی ندهید.
3. برای همه کارکنان در سامانه حساب جدا با رمز قوی بسازید.
4. پشتیبان بیرون از هاست (بخش ۷).

**محدودیت هاست اشتراکی:** سرور با سایت‌های دیگر مشترک است و فضای آن محدود است (حدود ۲ گیگابایت). برای معرفی خدمات، نوبت‌دهی و شروع کار مناسب است. وقتی پرونده سلامت و جواب آزمایش واقعی بیماران زیاد شد، انتقال به سرور اختصاصی داخل ایران توصیه می‌شود. بسته نصب آن آماده است ([DEPLOY.md](DEPLOY.md)).

## ۹. عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| خطای برنامه | `tail -100 ~/724/logs/724.log` |
| سایت باز نمی‌شود یا صفحه پیش‌فرض هاست می‌آید | در Application Manager ببینید برنامه 724 ثبت و Deploy شده باشد |
| هشدار گواهی یا باز نشدن HTTPS | بخش ۲ (Run AutoSSL) |
| خطای 400 (Bad Request) | آدرسی که باز کرده‌اید در `DJANGO_ALLOWED_HOSTS` در `.env` نیست |
| تغییر تنظیمات اعمال نشد | `touch ~/724/app/tmp/restart.txt` |
| بررسی تنظیمات امنیتی | `cd ~/724/app && ~/724/venv/bin/python manage.py check --deploy` |
| فضای پر | `du -sh ~/724/*` و حذف پشتیبان‌های قدیمی پس از دانلود |
